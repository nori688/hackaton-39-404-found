# Ночной реплей диспетчера — симулятор и игра

Сейчас это **стратегическая игра «Диспетчер участка»** поверх беспристрастного дискретно-событийного
симулятора. Сеть разветвлённая, с тремя выходами на соседние участки (Шалкар, Атырау, Узбекистан):
узел **Опорная** (примыкает линия на Атырау), узел **Бейнеу** (4 направления), узел **Сай-Утёс**
(тупик на Цемзавод) на ветке к порту Актау, узел **Жетыбай** (тупик на нефтяной Жанаозен) на ветке
к порту Курык, паромы через Каспий. Ветки примыкают к узлам с нужной горловины, и все маршруты
генератора проходят узлы насквозь, без разворота (`scenarios/build.py: throat_sides, straight`; тест).
Бэкенд — Python
(FastAPI), фронт — React (Vite).

```
backend/
  sim/            движок: model.py (данные), engine.py (события), observe.py (что видит политика), metrics.py
  dispatchers/    политики — ВНЕ движка: priority (автопилот-эвристика), scripted (записанный диспетчер)
  game.py         игровая сессия: игрок = такая же политика, пауза в моменты решений
  scenarios/      generator.py (случайные дни), build.py + day1/day2.json (ручные черновики)
  tests/          беспристрастность, генератор, игра, API
  api.py, cli.py
  replay/         ночной реплей: points.py (развилки и альтернативы), policies.py, runner.py (оценка и отчёт)
  sim/worlds.py   «мир, как его знал диспетчер» и ретро-мир для честной оценки
frontend/src/     Menu, Game, WorldMap + world.js (живая карта), SimpleHud, MapView/TrainGraph/Panels (диспетчер), Report, Replay + ReplayGraph
```

## Запуск

**Docker (проще всего):**

```bash
docker compose up -d --build      # http://localhost:8080
docker compose down
```

Два контейнера: `backend` (FastAPI + симулятор, реплей считает в нескольких процессах) и `frontend`
(nginx с собранным React, `/api` проксируется на backend). Ночной реплей в Docker Desktop идёт медленнее,
чем нативно, — столько ядер, сколько выдано виртуальной машине Docker.

**Без Docker (для разработки):**

```bash
cd backend && pip install -r requirements.txt && uvicorn api:app --port 8000
cd frontend && npm install && npm run dev        # http://localhost:5173
cd backend && python -m pytest -q tests          # тесты
```

## Как играть

Два режима одной и той же смены (переключаются кнопками «🗺 Карта» / «📈 Диспетчер» прямо в игре):

- **Простой — живая карта.** Участок в реальном масштабе: перегоны по длине в км, пути станций по полезной
  длине, поезда — по своей длине, из вагонов (контейнеры разноцветные, локомотив впереди). Колесо — зум
  к курсору, перетаскивание — панорама, двойной клик — камера следит за поездом. На мелком масштабе поезда
  укрупнены (иначе 1 км меньше пикселя) — об этом пишет подсказка внизу. Поезда едут сами (автопилот),
  игрок нажимает на поезд: «▶ Ехать», «⏸ Стоять», выбор порта; кружок-стрелка на узле переводит все
  контейнерные в Актау или Курык. Пауза только при сбоях. Видны светофоры на выходах, корабли в море с ETA,
  вагоны на путях порта в ожидании парома.
  Оформление — мультяшный вид сверху (`frontend/src/mapArt.js`): трава, щебень и шпалы, вокзалы с красной
  крышей, платформы со скамейками, фонарями и пассажирами, деревья, пруды, склады,
  у порта — краны и штабели контейнеров, у завода — силосы. Вагоны разные: пассажирские, платформы
  с контейнерами, лесовозы, крытые, цистерны, полувагоны. Ночью по игровым часам карта темнеет, горят фонари
  и фары. Декор не влияет на симуляцию.
- **Диспетчер — схема и график.** То, что описано ниже: график движения, ручные решения на каждом подходе.

Правила одни: карта рисуется из того же наблюдения, что получает любая политика, а между ответами
сервера поезда лишь плавно дорисовываются по номинальной скорости.

### Режим диспетчера

Вы — поездной диспетчер на смену. Время идёт со скоростью 1×–60× (пробел — пауза). Игра сама встаёт
на паузу, когда нужно решение: поезд подходит к станции (пропустить на проход или остановить),
поезд готов к отправлению, случился сбой, пришёл паром. Это настраивается в меню.

Приказы: отправить на следующую станцию; пропустить на проход у следующей станции, если будет свободно;
держать (бессрочно или 30 мин); выбрать порт на развилке; порядок погрузки на паром; автопилот —
для всех или для отдельных поездов. Незаконный приказ отклоняется с причиной и идёт в счёт.

В конце смены — сравнение с автопилотом **на том же дне** и раскрытие того, что было скрыто:
фактические опоздания против прогнозов, реальная длительность ремонтов, шторм и фактический приход паромов.

## Данные

**Синтетика (по умолчанию).** `scenarios/generator.py` строит случайный день по seed и уровням
трафика / сбоев / шторма. Тот же seed — тот же день. Границы реалистичны: перегоны 16–36 км, интервал
входа с соседнего участка не меньше 25 мин, длина составов согласована с путями (любые встречные могут
скреститься), прогнозы приходят заранее и ошибаются на ±15 мин, объявленная длительность ремонта —
40–110% фактической, при шторме ETA паромов уточняется ступенями. На тестах 36 случайных дней проходят
движок без нарушений инвариантов, а автопилот довозит все поезда в 77 из 80 дней.

**Данные станции (импорт).** Меню → «Данные станции» → JSON в формате сценария (шаблон скачивается
там же). Проверка — тем же загрузчиком (`POST /api/scenarios/validate`). Формат:

| Раздел | Что | Поля «правды» (скрыты от игрока до конца смены) |
|---|---|---|
| `nodes` | станции/разъезды/порты, пути с полезной длиной и видом (`main`/`port`) | — |
| `segments` | перегоны: концы, длина, ограничение скорости | — |
| `train_types` | скорость, потери на разгон/торможение, вес в метрике | — |
| `trains` | маршрут, плановое время, длина, вагоны, остановки, прогнозы опозданий | `appear_actual` |
| `ferries` | порт, вместимость, плановый приход, обновления ETA | `actual_arrival` |
| `disruptions` | поломки, закрытия перегонов, окна | фактическая `duration_min` |

Для живых данных КТЖ достаточно адаптера, который собирает этот JSON из выгрузки (график движения,
натурный лист, паспорт станции) — движок и игра не меняются.

API игры: `POST /api/game` (`generate` | `scenario` | `scenario_data`), `POST /api/game/{id}/advance {dt}`,
`/resume`, `/command`, `GET /api/game/{id}/report`.

## Ночной реплей

Запуск: после смены в итогах — «🌙 Ночной реплей: разобрать мои решения»; в меню — для готового сценария
(вёл записанный диспетчер) или случайного дня (вёл автопилот). API: `POST /api/replay`
(`game` | `scenario` | `generate`), `GET /api/replay/{id}`, `GET /api/replay/{id}/compare/{card}`.

1. **Факт воспроизводится тем же движком.** Сыгранная смена — по журналу решений, включая приказы «сейчас»
   между событиями (тест: воспроизведение совпадает байт в байт).
2. **Точки решений и 2–3 альтернативы** строятся только из того, что было на табло в этот момент:
   кого первым на перегон; скрестить здесь, а не на следующей станции; дать обгон более важному;
   отправить сразу, а не держать; другой порт; порядок погрузки на паром; как поступил бы автопилот.
   Альтернатива, которую движок бы отклонил, не считается.
3. **Остаток дня перепрогоняется** для решения смены и для каждой альтернативы одним и тем же продолжением
   (та же политика, что в факте; для живого игрока — автопилот с его приказами о портах). Разница — эффект
   именно этого решения.
4. **Два режима оценки**, в каждом по 4 варианта будущего:
   - *как ожидал диспетчер* — будущее из знания на момент решения: прогнозы (с их погрешностью),
     объявленные сроки ремонтов, без сбоев, о которых не сообщили (`sim/worlds.py`; тест: наблюдение
     в этом мире совпадает с настоящим);
   - *как прошёл день* — настоящие события, заново разыгранный мелкий разброс времени хода.
   Вывод «лучше / хуже» — только если согласны 3 из 4 вариантов, по медиане и по среднему.
   Зачем: одиночный прогон часто случаен — малая разница во времени хода раскачивает весь день.
5. **Отчёт**: упущенные возможности (лучше по знанию того момента), жертва ради нескольких (придержанный
   поезд теряет, двое и больше выигрывают), удачные решения (все альтернативы хуже), лучше алгоритма,
   невезение (лучше только с учётом того, чего знать было нельзя, — с перечнем этих событий), проблемные
   разъезды. «Было / могло быть» — наложение графиков движения с моментом решения.

На ноутбуке с 4 ядрами день 1 (48 развилок, 800 прогонов дня) считается ~40 с.

## Что значит «бескомпромиссный»

Симулятор один и тот же для факта смены и для любой альтернативы. Тот, кто принимает решения
(человек, скрипт, ИИ), для движка — чёрный ящик: получает словарь-наблюдение, возвращает команды.

| Гарантия | Как обеспечена | Тест |
|---|---|---|
| Политика не видит будущего | наблюдение строится только в `observe.py`: прогнозы — лишь объявленные к моменту t, сбои — после факта и с **объявленной** длительностью, ETA — номинальное, без шума | `test_hidden_future_does_not_leak`, `test_running_noise_not_visible`, `test_failure_shows_announced_not_actual_duration` |
| Ретро-режим не включается тайно | `oracle` — отдельный режим с явным разделом `oracle` в наблюдении | `test_oracle_is_explicit` |
| Одинаковое «везение» | шум времени хода зависит только от (seed, поезд, перегон); сбои привязаны ко времени сценария | `test_running_noise_independent_of_decisions` |
| Команды не исправляются | незаконная команда отклоняется с причиной и считается в метрике, состояние не меняется | `test_reject_*` |
| Остановка стоит денег | торможение + разгон + приготовление маршрута; «пропустить на проход» можно только в момент подхода (за 3 мин), позже поезд уже тормозит | `test_stop_costs_brake_accel_and_setup`, `test_through_decision_only_at_approach` |
| Тупики не разруливаются | сцепка = конец дня, задержки копятся до горизонта; бездействие политики помечается отдельно (`stalled`) | `test_deadlock_is_reported_not_resolved` |
| Политика не может сломать движок | получает глубокую копию наблюдения | `test_policy_cannot_mutate_engine` |
| Детерминизм и форки | одинаковый вход → байт-в-байт тот же результат; форк в середине дня = непрерывный прогон | `test_deterministic`, `test_fork_equals_uninterrupted` |

Правила (одинаковые для всех): перегон — 1 поезд (полуавтоблокировка); отправить можно только
при свободном перегоне **и** свободном пути подходящей длины на следующей станции (согласие на приём);
длинный контейнерный (1000 м) не встаёт на короткий путь разъезда (850 м); пассажирский не уходит
раньше расписания и не может проследовать обязательную остановку; известное «окно» нельзя занять, если поезд не успевает освободить перегон по номиналу; на необъявленное окно поезд пустить можно, тогда бригада ждёт, окно сдвигается, и это штраф. Порт: вагоны
грузятся после обработки (60 мин) по 3 мин/вагон, путь порта освобождается только после погрузки
последнего вагона; паром ждёт причала, разгружается, уходит полным или по истечении стоянки.

## Допущения модели (симметричны для факта и альтернатив)

- Сбой локомотива привязан к моменту времени: в альтернативе поезд может оказаться в другом месте, но сбой его всё равно настигнет.
- Маршрут, установленный перед поездом, при его поломке не отменяется (команды отмены пока нет).
- Локомотив, приведший состав в порт, дальше не моделируется; паромы только забирают вагоны.
- Сценарии `day1`/`day2` — черновики для проверки движка; драматургию демо (жертва, невезение, «диспетчер лучше алгоритма») ещё предстоит прописать.

## Команды политики

```json
{"type": "dispatch", "train": "C203", "next": "RA", "track": "1"}   // track — необязательно
{"type": "wake_at", "time": 37800}                                   // разбудить в 10:30
{"type": "ferry_order", "port": "AKTAU", "order": ["C203", "C201"]}
```
В наблюдении есть `legal` — список отправлений, которые прямо сейчас будут приняты.
Его считает тот же код, что валидирует команды, и видят его все политики одинаково.
